# 松果集市 容器部署优化

> 更新日期：2026-08-26  
> 入口：`NewSecondMall-启动面板.cmd`

日常开发仍用面板第 1、3 项（本机 8080 + H5 预览 5173）。Docker 是另一套环境，不要和本机 Spring Boot 混开。Docker 部署已改为多阶段构建，新机器不需要 Maven 或 HBuilderX。

---

## 1. 前后对比

| | 优化前 | 优化后 |
|--|--|--|
| 怎么部署 | 本机手打 JAR、HBuilderX 菜单发行 H5、再手动 `compose up` | `docker compose up --build` 在容器构建阶段自动编译 |
| 前端产物目录 | 依赖 HBuilderX 生成的 `h5/` 或 `web/` | Node 构建阶段执行 `npm ci` + `npm run build:h5` |
| 库密码 | `.env` 里是占位符，对不上就直接报错退出 | 第 9 项当场询问，写入 `deploy/.env` |
| Nginx | `/api/` `/files/` `/ws/` 三处都写死 `http://backend:8080` | 具名 upstream，拆服务以后只改顶部三行 |
| 对外端口 | 已只开 Nginx 80 | 保持：backend / mysql 不映射端口 |
| 停、删、启 | 要记 compose 命令 | 面板 10 / 12 / 13 分开 |

没做的：不把 HBuilderX 放进 Linux 镜像编译；不改探活（仍 GET `/api/products`）；不拆微服务。

## 2. 新的 Docker 部署流程

```
启动面板 第 9 项
  └─ docker compose up --build
       ├─ Maven 构建阶段 → JAR
       └─ Node/uni CLI 构建阶段 → H5 静态文件
        ↓
mysql 容器（数据在卷 mysql_data）
  → backend 容器（JAR，8080 仅内网）
    → frontend 容器（Nginx :80 对外）
```

浏览器只访问 Nginx（默认 `http://localhost`）。`/api/`、`/files/`、`/ws/` 由 Nginx 转到 backend。

**实现要点**

- 编排：`deploy/docker-compose.yml`，密钥在 `deploy/.env`（gitignore，不进镜像）。
- 后端镜像：`deploy/backend.Dockerfile`，Maven 多阶段构建 JAR，JRE 运行。
- 前端镜像：`deploy/frontend.Dockerfile`，Node/uni CLI 编译 H5，Nginx 运行静态资源。
- Nginx：`deploy/nginx/default.conf`，`upstream_api` / `upstream_files` / `upstream_ws` 目前都指向 `backend:8080`。
- 面板脚本：`NewSecondMall-LaunchPanel.ps1`。第 9 项只负责准备 `.env` 并调用 Compose，构建不再依赖 HBuilderX。

容器里的 MySQL 和本机 MySQL 是两套库。官方 MySQL 镜像只在**空数据卷第一次启动**时用 `.env` 建用户；之后改密码不会改卷里已有账号。对不上时用第 12 项删库，再第 13 项启动。

### 第一次启动怎么写密码

选第 9 项。若 `deploy/.env` 不存在或还是占位符，面板会询问，**不是**本机 Navicat / Windows MySQL 的 root 密码，给容器里新建的库随便定一组即可。

| 提示 | 怎么填 |
|------|--------|
| 数据库用户名 `[shop_user]` | 直接回车，用 `shop_user` |
| 应用密码 DB_PASSWORD（输入时不显示） | 自己定一个，不能空。这是 backend 连库用的密码 |
| 容器 MySQL root 密码（回车则与上面相同） | 课设直接回车即可 |
| 浏览器访问地址 PUBLIC_ORIGIN `[http://localhost]` | 本机 Docker 直接回车。若改过 `HTTP_PORT`（例如 8088），写成 `http://localhost:8088` |

填完会写入 `deploy/.env`，以后第 9 / 13 项不再问。`.env` 不要提交到 Git。

密码输入时屏幕上没有回显，属正常。记住自己填的那一组；换密码不会改已经建好的数据卷，要对齐只能第 12 项删库后再启动。

## 3. 启动面板新增项

| 项 | 作用 | 实际命令 |
|----|------|----------|
| **9. 构建并启动 Docker** | 改了代码或第一次部署。问容器库用户名/密码（写入 `.env`）→ Docker 内编译前后端 → 启动容器 | `docker compose up -d --build` |
| **10. 停止容器** | 确认后停止本项目全部容器（mysql / backend / frontend），库还在。QUIT 取消 | `docker compose stop` |
| **11. 查看容器状态** | 看三个容器是否 Up / healthy | `docker ps -a`（`deploy-`） |
| **12. 删除容器数据库** | 确认后删 Docker 里的库。YES 执行，QUIT 返回菜单。删完**不会**自动启动 | `docker compose down -v` |
| **13. 重新启动容器** | 用现成镜像再拉起来，不打 JAR、不发行 H5 | 先 `compose start`，不行再 `up -d` |

怎么用：

- 日常关/开：10 → 13。
- 改了前后端：9。
- 容器库密码对不上、或要空库：12 → 13。
- 第 3 项是开发预览（5173），第 9 项才是进 Nginx 的发行构建。

## 4. 拆成微服务后修改办法

现在还是一个 Spring Boot。拆分时 **浏览器入口不变**（仍只开 Nginx 80），H5 仍请求 `/api/`、`/files/`、`/ws/`。改的是容器内部谁接这些前缀。

**1. Compose 多几个后端服务**

`deploy/docker-compose.yml` 里把现在的 `backend` 换成例如 `shop`、`chat`、`auth`，各 COPY 自己的 JAR。mysql、frontend 可以留。每个新服务都进 `shop_internal`，**不要**再映射 8080。frontend 的 `depends_on` 改成依赖真正对外的那些服务（或改成 `service_started`，避免绑死某一个探活）。

**2. Nginx 只改 upstream 的 `server`**

`deploy/nginx/default.conf` 顶部现在是：

```nginx
upstream upstream_api     { server backend:8080; }
upstream upstream_files   { server backend:8080; }
upstream upstream_ws      { server backend:8080; }
```

拆完后例如：

```nginx
upstream upstream_api     { server shop:8080; }
upstream upstream_files   { server shop:8080; }
upstream upstream_ws      { server chat:8080; }
```

`location /api/` 等块不用动。若登录要单独前缀，再加一个 `upstream` 和 `location`，不要把整站收成一个 `location /` 反代。

**3. 探活不要再绑 `/api/products`**

`backend.Dockerfile` 里 `HEALTHCHECK` 现在 GET `/api/products`。auth / chat 服务没有这条接口会一直 unhealthy，frontend 也起不来。拆开后各服务改成自己的探活（例如 `/actuator/health`），或 Compose 里不要用 `condition: service_healthy` 去等一个已不存在的路径。

**4. 面板第 9 项：多打几个 JAR**

流程仍是 `docker compose up --build`，但需要在各服务 Dockerfile 的构建阶段分别编译对应模块，或由父 POM 一次打出多个 JAR。第 10～13 项命令不用变，只是容器变多，第 11 项会看到更多 `deploy-*`。

**5. 不必重做的部分**

- 仍然只暴露 Nginx；密钥仍走 `.env`。
- 前端不用改域名去指向 `shop` / `chat`（浏览器解析不了这些主机名）。
- 一服务一库、JWT 跨服务，另开设计和文档，不是改这三处配置就能完成的。

## 第 0 步 · 通用准备（只做一次）

1. 打开 Windows 截图工具：按 `Win + Shift + S` 可框选截图；或设置里打开"PrintScreen 键直接截图"。
2. 截图统一保存到仓库 `docs/images/` 目录，命名规范：`编号-内容-日期.png`，例如 `03-流水线成功-20260903.png`。
3. 打开 PowerShell 和 Git Bash 各一个窗口，字体调大（`Ctrl + 滚轮`），方便后排看清。
4. 提前登录好以下三个页面并保持标签页打开：
   - CodeArts 流水线控制台（华为云 CodeArts → 本项目 → 流水线）
   - CodeArts 看板（Scrum 项目看板）
   - 系统前台页面 `http://120.46.222.10`（或本地 `http://localhost:5173`）
5. 准备 SSH 终端登录服务器 `120.46.222.10`（K8s 集群在服务器上，kubectl 命令加 `sudo` 执行）。
6. 确认测试账号可用：买家 `demo / demo123`，管理员 `admin / admin123`。
7. 建议同时开 OBS 录屏做 5~8 分钟备用录屏（任务书允许网络故障时本地演示，但录屏不能代替现场检查）。

## 第二部分 · 现场演示 7 分钟脚本（答辩当天按顺序做）

> 任务书要求现场优先演示可重复的过程。以下每步都对应一个"现场要看到什么"。

1. **（约 1 分钟）push 触发流水线**
   - 终端：`git commit --allow-empty -m "demo: trigger pipeline" && git push origin master`
   - 切到 CodeArts 流水线页面 → 评委看到新一次运行开始。
2. **（约 1 分钟）查看 K8s 部署**
   - SSH：`sudo kubectl -n shop get deploy,pods,svc,hpa` → 指出 4 个业务微服务 + 前端 + MySQL + HPA。
   - `bash ops/remote-health.sh http://120.46.222.10` → 健康检查输出 "Health check succeeded"。
3. **（约 2 分钟）跑 1 个重点用例（建议"下单全流程"）**
   - 浏览器：登录 demo/demo123 → 商品详情 → 加购物车 → 结算下单 → 模拟支付 → 订单列表看到新订单。
   - 口头说明：这一步跨了 user-service（鉴权）、catalog-service（商品）、trade-service（订单）三个服务。
4. **（约 1.5 分钟）触发扩缩容**
   - 先 `sudo kubectl -n shop get hpa,pods` 展示 1 副本；
   - 本地跑 `npm run test:performance:catalog`；`-w` 窗口展示副本往上涨即停（现场不必等缩容，用第 6 节截图补完整过程）。
5. **（约 1 分钟）停掉一个依赖服务**
   - `sudo kubectl -n shop scale deployment catalog-service --replicas=0`
   - 刷新商品页 → 看到设计好的错误提示；再点开话题/登录页 → 其他服务正常。
   - **演示完立即恢复**：`sudo kubectl -n shop scale deployment catalog-service --replicas=1`。
6. **（约 0.5 分钟）收尾**
   - 展示流水线已变绿（第 1 步触发的那次跑完）→ "一次 push 完成构建、测试、镜像、部署、健康检查"。

## 附 · 常见翻车点

- 截图前把终端无关输出 `clear` 掉，画面只留关键命令和结果。
- HPA 缩容有 300 秒稳定窗口，现场演示不要等缩容，用预录截图补。
- 公网 Nginx 入口有 30r/s 限流，HPA 正式实验必须按实验文档走 SSH 隧道 + port-forward 直连，否则 503 会污染数据。
- 故障处理演示后**务必恢复副本数**，否则影响后续演示和验收。
- 所有截图当天就拷进 `docs/images/` 并提交，避免最后一天补图。

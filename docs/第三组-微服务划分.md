# 微服务划分
## 微服务划分图

```mermaid

    FE[前端 / 客户端] --> GW[API 网关：统一入口、路由、鉴权、限流]
    GW --> U[user-service<br/>用户服务 :8081]
    GW --> C[catalog-service<br/>商品服务 :8082]

    T --> TDB[(trade_db)]

    T -->|商品快照 / 标记已售| C
    U -->|中心聚合接口| C
    U -->|中心聚合接口| T
    I -->|批量用户摘要| U
    I -->|批量商品摘要| C
```

> 本文档描述微服务改造后的目标架构、接口归属和数据归属。当前代码仍为单体版本；后续改造时，各服务应能独立构建、测试和部署。

服务职责说明

|服务|主要职责|划分理由|
|:-:|:-:|:-:|
|用户服务 `user-service`|注册登录、身份认证、个人资料、实名认证、信用、收货地址、用户管理|都围绕用户身份及用户生命周期，安全要求和数据一致性相近|
|商品服务 `catalog-service`|商品、店铺、收藏、浏览记录、关注店铺、商品审核、图片上传|商品和店铺是交易平台的核心目录，查询量大，适合作为独立扩容单元|
|交易服务 `trade-service`|购物车、下单、订单状态、取消订单、评价|具有明确交易事务边界，后续可单独进行订单压力测试|
|互动与智能服务 `interaction-service`|话题、帖子、评论、点赞、关注话题、帖子行为、会话、消息、已读状态、AI 议价、AI 助手、WebSocket|社区互动、即时会话与智能能力均属于用户互动域，与交易核心流程耦合较低|

### 数据访问约束

1. 每张业务表只能由所属服务直接读写，其他服务不能直接访问该表。
2. 各服务可以共用一个 MySQL 实例，但应使用不同的数据库或 Schema。
3. 服务之间只保存逻辑业务 ID，不建立跨数据库外键，也不执行跨库 JOIN。
4. 跨服务数据访问必须通过 REST 接口、事件或消息完成。
5. 订单应保存下单时的商品名称、成交价格等必要快照，避免商品后续修改影响历史订单。

## 跨服务调用与失败处理

### 1. 创建订单

调用流程：

1. 前端通过 API 网关调用交易服务创建订单。
2. 交易服务调用用户服务，校验用户状态和收货地址归属。
3. 交易服务调用商品服务，查询商品快照，并校验商品是否审核通过、是否可售。
4. 交易服务保存订单以及商品名称、成交价格等交易快照。
5. 交易服务调用商品服务，将对应商品标记为已售。

失败处理：

- 用户服务不可用时，交易服务在超时后终止下单，不写入订单。
- 商品服务不可用、商品不存在或商品不可售时，不创建订单。
- 订单已经创建，但商品标记为已售失败时，记录补偿任务并进行有限重试；最终失败则取消订单。
- 创建订单请求携带唯一业务号，保证重复请求或重试不会产生重复订单。

### 2. AI 议价

调用流程：

1. 前端通过 API 网关调用互动与智能服务发起 AI 议价。
2. 互动与智能服务调用商品服务，查询商品状态、当前价格和最低价。
3. 互动与智能服务生成议价建议并保存消息。
4. 互动与智能服务通过 WebSocket 将结果推送给用户。

失败处理：

- 调用商品服务时设置超时时间，避免请求长期阻塞。
- 商品服务暂时不可用时，优先使用短期缓存的商品摘要。
- 没有可用缓存时，返回“商品信息暂时不可用，请稍后重试”的备用结果。
- AI 模型不可用时，使用规则生成备用议价建议，普通聊天功能仍然保持可用。

该场景可用于课程要求的故障处理实验：主动停止商品服务，验证 AI 议价返回预先设计的备用结果，并确认其他服务不会发生级联故障。

### 3. 买家中心和卖家中心

调用流程：

1. 用户服务查询用户基本信息、实名认证和信用数据。
2. 用户服务调用商品服务，获取收藏、足迹、关注店铺和发布商品统计。
3. 用户服务调用交易服务，获取订单数量、待处理订单和销售额。
4. 用户服务聚合各服务结果后返回前端。

失败处理：

- 某个下游服务不可用时，仍然返回用户基本信息。
- 不可用模块的数据暂时置空，并返回 `partial=true` 和 `unavailableModules`。
- 聚合接口不因单个依赖服务发生故障而整体失败。
- 商品、订单等列表数据通过批量接口查询，避免逐条远程调用。

### 4. 社区内容展示

调用流程：

1. 互动与智能服务调用用户服务，批量查询帖子作者的公开信息。
2. 互动与智能服务调用商品服务，批量查询帖子关联的商品和店铺摘要。

失败处理：

- 用户服务不可用时，使用短期缓存或显示匿名作者。
- 商品服务不可用时，隐藏关联商品卡片，但帖子正文仍然正常展示。
- 使用批量查询接口和短期缓存，避免列表页面产生大量跨服务调用。

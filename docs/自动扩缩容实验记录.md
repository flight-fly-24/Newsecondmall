## 4. 压测命令

先设置本机 JMeter 路径：

```powershell
$env:JMETER_HOME = 'D:\Tools\apache-jmeter-5.6.3'
```

基线测试快捷命令：

```powershell
npm run test:performance:baseline -- -HostName 120.46.222.10 -Port 80 -Protocol http
```

HPA 扩容测试快捷命令：

```powershell
npm run test:performance:hpa -- -HostName 120.46.222.10 -Port 80 -Protocol http
```

catalog-service 专用 HPA 压测（不依赖登录和其他微服务）：

```powershell
npm run test:performance:catalog -- -HostName 120.46.222.10 -Port 80 -Protocol http
```

自定义参数：

```powershell
npm run test:performance -- -HostName 127.0.0.1 -Port 8080 -Threads 50 -RampSeconds 30 -DurationSeconds 120
```

命令含义：

| 命令 | 用途 |
|---|---|
| `test:performance` | 自定义主机、端口、并发数、升压和持续时间 |
| `test:performance:baseline` | 20 线程、20 秒升压、持续 60 秒的基线测试 |
| `test:performance:hpa` | 100 线程、30 秒升压、持续 300 秒的扩缩容实验 |
| `test:performance:catalog` | 只循环请求商品列表的 catalog-service HPA 实验 |

正式实验前检查集群、Metrics Server、Deployment、CPU requests 和 HPA：

```powershell
npm run test:hpa:check
```

在另一个终端持续采集十分钟 HPA 指标并生成 CSV：

```powershell
npm run test:hpa:watch -- -IntervalSeconds 10 -DurationSeconds 600
```

报告生成在 `tests/performance/results/<时间戳>/report/index.html`。

## 6. 扩容过程

观察命令：

```bash
kubectl -n shop get hpa,pods -w
kubectl -n shop top pods
kubectl -n shop describe hpa catalog-service
```

| 时间点 | 平均 CPU 利用率 | HPA 目标值 | Pod 数量 | 事件或说明 |
|---|---:|---:|---:|---|
| T+0 | 待测 | 50% | 1 | 开始压测 |
| 压力上升 | 47% | 50% | 1 | 接近扩容阈值 |
| 扩容触发 | 265%～350% | 50% | 1 → 3 | 首次扩容 |
| 持续高压 | 188%～69% | 50% | 3 → 4 | 扩到最大副本数 |
| 压测停止 | 13% → 1% | 50% | 4 | 进入 300 秒缩容稳定窗口 |

## 7. 缩容过程

| 停止压测后的时间 | Pod 数量 | CPU 利用率 | 说明 |
|---|---:|---:|---|
| 0 分钟 | 4 | 约 1%～5% | 停止压测 |
| 3 分钟 | 4 | 约 1%～4% | 稳定窗口内 |
| 5 分钟左右 | 2 | 2% | 开始缩容 |
| 随后约 1 分钟 | 1 | 1% | 恢复最小副本数 |

## 8. 性能结果

| 测试阶段 | 请求数 | 吞吐量 | 平均响应时间 | P95 | 最大响应时间 | 错误率 |
|---|---:|---:|---:|---:|---:|---:|
| catalog HPA 有效实验 | 21,933 | 365.91 请求/秒 | 45.96 ms | 108 ms | 438 ms | 0% |

首次通过公网 Nginx 入口执行的测试受到 `30r/s`、`burst=60` 限流影响，出现大量由网关返回的 HTTP 503，且请求未充分到达 catalog-service，因此不作为 HPA 性能结论。正式实验通过 SSH 隧道和 Kubernetes 端口转发直连 ClusterIP Service，未向公网暴露服务端口。

## 10. 实验结论

- 是否成功扩容：是，Pod 从 1 扩到 3，随后扩到 4
- 是否成功缩容：是，Pod 从 4 缩到 2，随后恢复到 1
- 最大 Pod 数量：4
- 峰值吞吐量：365.91 请求/秒（本次 60 秒有效实验的整体吞吐量）
- 平均响应时间：45.96 ms
- P95 响应时间：108 ms
- 错误率：0%
- 异常和改进建议：公网入口存在 30r/s 限流，HPA 压测应在受控网络中直连目标服务；公网入口测试应单独验证限流策略，不能与服务扩缩容性能混为一谈。

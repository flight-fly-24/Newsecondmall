## 1. 环境要求

### 1.1 硬件要求

| 组件 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU  | 2 核    | 4 核及以上 |
| 内存 | 4 GB    | 8 GB 及以上 |
| 磁盘 | 10 GB   | 20 GB 及以上（SSD 优先） |

### 1.2 软件环境

| 软件 | 版本要求 | 用途 |
|-----|---------|------|
| JDK | 21+ | 运行后端 Spring Boot 服务 |
| Maven | 3.9+ | 后端项目构建与依赖管理 |

| Node.js | 18+ (可选) | 前端构建（HBuilderX 内置） |
| Docker Desktop | 最新稳定版（课设容器部署） | 运行 mysql / backend / frontend 容器 |
| HBuilderX | 最新稳定版 | uni-app 本地开发（Docker 部署不依赖 HBuilderX） |
| Nginx | 1.20+ (生产必需) | 静态资源服务与 API 反向代理 |
|微信开发者工具 | 最新版 (可选) | 微信小程序调试 |

## 3. 数据库部署

### 3.1 创建数据库

登录 MySQL 并执行：

```sql
CREATE DATABASE IF NOT EXISTS shop_db
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;
```

### 3.2 创建业务账号（可选）

```sql
CREATE USER 'shop_user'@'localhost' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON shop_db.* TO 'shop_user'@'localhost';
FLUSH PRIVILEGES;
```

### 3.3 初始化表结构

```bash
mysql -u root -p shop_db < shopping_back/shopping_back/doc/db.sql
```

若 MySQL 中已有 `shop_db`，也可在登录后执行：

```sql
source ./shopping_back/shopping_back/doc/db.sql;
```

## 4. 后端部署

### 4.1 配置环境变量

在启动后端前，需要设置以下环境变量：

| 变量名 | 说明 | 默认值 |
|-------|------|--------|
| `DB_URL` | MySQL 连接地址 | `jdbc:mysql://localhost:3306/shop_db?serverTimezone=UTC&useUnicode=true&characterEncoding=UTF-8&allowPublicKeyRetrieval=true&useSSL=false` |
| `DB_USERNAME` | 数据库用户名 | `shop_user`（本地开发） |
| `DB_PASSWORD` | 数据库密码 | 无生产默认值，必须通过安全变量注入 |
| `AI_BARGAIN_API_KEY` | AI 议价 API Key | 无默认值，必须通过安全变量注入 |
| `DASH_SCOPE_API_KEY` | 商品发布建议 AI 的 Key | （可选） |

Windows PowerShell 设置示例：

```powershell
$env:DB_USERNAME="shop_user"
$env:DB_PASSWORD="你的数据库密码"
```

严禁将数据库密码、Token、私钥或 AI Key 写入代码、配置模板、流水线脚本和文档。曾经提交到仓库的密钥必须立即在对应平台吊销并重新生成；仅从仓库删除不能消除泄漏风险。

### 4.2 启动后端服务

```powershell
cd 松果集市/shopping_back/shopping_back
mvn spring-boot:run
```

启动成功后日志显示：

```
Started ShoppingBackApplication in X.XXX seconds
```

**默认端口：8080**

若端口被占用，可在 `application.properties` 中修改：

```properties
server.port=8081
```

并在前端 `manifest.json` 中同步修改代理目标端口。

### 4.3 验证后端

访问接口确认启动成功：

```bash
curl http://localhost:8080/api/products
```

预期返回：

```json
{"code": 0, "message": "ok", "data": [...]}
```

## 5. 前端部署

### 5.1 H5 部署（本机 / 自建 Nginx）

容器部署请用第 6 节（启动面板第 9 项会发行 H5 并打进 frontend 镜像），不必再手工拷到本机 Nginx。

使用 HBuilderX 打开 `shopping_front` 目录：

1. 菜单栏：发行 → 网站-H5手机版
2. 构建产物目录：`shopping_front/unpackage/dist/build/h5/`
3. 将该目录文件部署到 Nginx 静态目录

### 5.2 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/shop-h5;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket 代理（用于聊天功能）
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 5.3 微信小程序部署

1. 使用 HBuilderX 打开 `shopping_front`
2. 菜单栏：发行 → 小程序-微信
3. 在微信开发者工具中打开构建产物目录
4. 配置合法域名（小程序后台 → 开发 → 服务器域名）：
   - `request` 合法域名：后端 API 地址
   - `socket` 合法域名：WebSocket 地址（如 `wss://your-domain.com`）

## 6. Docker 部署

入口：项目根目录 `NewSecondMall-启动面板.cmd`。详细对比与拆微服务说明见 `docs/容器部署优化.md`。

Docker 里的 MySQL、后端、前端与第 3～5 节的本机环境是**另一套**。容器内 8080 不映射到宿主机；浏览器只打开 Nginx（默认 `http://localhost`）。

### 6.1 流程

```
启动面板 第 9 项
  └─ docker compose up --build
       ├─ Maven 构建阶段 → JAR
       └─ Node/uni CLI 构建阶段 → H5 静态文件
        ↓
mysql 容器（数据在卷 mysql_data）
  → backend 容器（JAR，8080 仅内网）
    → frontend 容器（Nginx :80 对外）
```

`/api/`、`/files/`、`/ws/` 由容器内 Nginx 转到 backend。后端由 Maven 构建阶段编译，前端由 Node/uni CLI 构建阶段编译，宿主机不需要预先生成 JAR 或 H5 产物。

相关文件：`deploy/docker-compose.yml`、`deploy/backend.Dockerfile`、`deploy/frontend.Dockerfile`、`deploy/nginx/default.conf`。密码在 `deploy/.env`（gitignore，不进 Git、不进镜像）。

### 6.2 第一次启动：怎么写密码

安装 Docker Desktop 并保证 `docker` 可用。双击启动面板，选 **9. 构建并启动 Docker**。

若还没有 `deploy/.env` 或仍是占位符，面板会询问。这是给**容器里新建的 MySQL**定的口令，**不是**本机 Navicat / Windows MySQL 的 root 密码。

| 提示 | 怎么填 |
|------|--------|
| 数据库用户名 `[shop_user]` | 直接回车，用 `shop_user` |
| 应用密码 DB_PASSWORD（输入时不显示） | 自己定一个，不能空。backend 连库用这个 |
| 容器 MySQL root 密码（回车则与上面相同） | 课设直接回车即可 |
| 浏览器访问地址 PUBLIC_ORIGIN `[http://localhost]` | 本机直接回车。若 `.env` 里 `HTTP_PORT` 不是 80（例如 8088），写成 `http://localhost:8088` |

填完写入 `deploy/.env`，以后第 9 / 13 项不再问。输入时屏幕无回显属正常。

官方 MySQL 镜像只在**空数据卷第一次启动**时用 `.env` 建用户。之后改 `.env` 不会改卷里已有密码。对不上（backend `Access denied`）时用第 12 项删容器库，再第 13 项启动。第 12 项不影响本机 MySQL。

### 6.3 启动面板 Docker 相关项

| 项 | 作用 | 实际命令 |
|----|------|----------|
| **9. 构建并启动 Docker** | 第一次部署或改了代码。询问密码 → Docker 内编译前后端 → 起容器 | `docker compose up -d --build` |
| **10. 停止容器** | 先确认。停止本项目全部三个容器，库还在。QUIT 取消 | `docker compose stop` |
| **11. 查看容器状态** | 看 mysql / backend / frontend 是否 Up、healthy | `docker ps -a`（名称含 `deploy-`） |
| **12. 删除容器数据库** | 只删 Docker 里的库和上传文件。YES 确认，QUIT 退出。删完不会自动启动 | `docker compose down -v` |
| **13. 重新启动容器** | 不打 JAR、不发行 H5，用现成镜像再拉起 | 先 `compose start`，不行再 `up -d` |

怎么用：

- 日常关/开：10 → 13。
- 改了前后端：9。
- 容器库密码对不上、或要空库：12 → 13。
- 面板第 3 项是开发预览（localhost:5173）；第 9 项才是进容器 Nginx 的发行构建。

三个容器均为 healthy 后，浏览器打开 `PUBLIC_ORIGIN`（默认 `http://localhost`）验收首页、登录、`/api/`、上传 `/files/`、聊天 `/ws/`。

## 7. 前后端联调配置

### 7.1 H5 开发代理配置

`shopping_front/manifest.json` 中已预配置 devServer proxy：

```json
"h5": {
  "devServer": {
    "port": 8000,
    "proxy": {
      "/api": {
        "target": "http://127.0.0.1:8080",
        "changeOrigin": true
      }
    }
  }
}
```

### 7.2 CORS 配置

后端 `application.properties` 中配置允许的跨域来源：

```properties
app.cors.allowed-origin-patterns=${APP_CORS_PATTERNS:http://localhost:*,http://127.0.0.1:*}
```

生产环境务必改为实际前端域名。

## 8. 生产环境注意事项

1. **HTTPS**：H5 部署必须使用 HTTPS，微信小程序强制要求 HTTPS
2. **API Key 保护**：AI 议价 API Key 应通过环境变量注入，不硬编码在配置文件中
3. **数据库连接池**：生产环境建议调整连接池大小，避免连接耗尽
4. **日志**：建议配置日志文件滚动策略和日志级别（ERROR/WARN）
5. **监控**：建议接入 Spring Boot Actuator 进行健康检查
6. **会话管理**：Token 应设置合理过期时间，生产环境建议使用 Redis 存储会话

## 9. 故障排除

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| 端口 8080 被占用 | 其他进程占用端口 | `netstat -ano \| findstr :8080` 找到 PID 并 `taskkill /PID <PID> /F`，或修改 `server.port` |
| 数据库连接失败 | 环境变量未设置或 MySQL 未启动 | 检查 `DB_URL`/`DB_USERNAME`/`DB_PASSWORD` 是否正确，确认 MySQL 服务运行中 |
| Maven 构建失败 | 网络问题或依赖缓存损坏 | 尝试 `mvn clean package -U` 强制更新依赖 |
| 前端请求 404 | 代理未配置或后端未启动 | 检查 `manifest.json` proxy 配置和后端启动状态 |
| 前端请求跨域 | CORS 配置未生效 | 检查 `app.cors.allowed-origin-patterns` 配置 |
| Docker 第 9 项 backend Restarting / Access denied | `.env` 密码与已有 mysql 数据卷不一致 | 面板第 12 项删容器库，再第 13 项启动 |
| Docker frontend 起不来 | 在等 backend healthy | 第 11 项看 backend 是否 Up (healthy)；不要和本机 8080 那套混用 |
| Docker 80 端口占用 | 本机已有 Nginx/IIS | `deploy/.env` 改 `HTTP_PORT=8088`，`PUBLIC_ORIGIN=http://localhost:8088` 后重新第 9 或 13 项 |
